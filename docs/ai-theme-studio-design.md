# AI 主题设计助手：首版设计

状态：产品范围已由用户确认，首版已实现；使用与限制见 [AI 主题设计助手](ai-theme-studio.md)。真实 Electron 宿主与模型提供方仍需运行验证。

## 目标与边界

在现有外观工作室内，用户通过多句描述和参考图片，与 AI 多轮交互生成主题草稿。每轮校验并预览，满意后保存应用。

首版提供插件内部的模型调用接口。对外供其他 AI 调用的工具接口留待后续，不属于本次实现范围。复用 DSH 模型、凭据、附件与现有主题能力。

只处理现有主题配置可表达的配色、字体、壁纸设置、材质、圆角、透明度、氛围等。无法表达的参考效果要说明限制；不生成任意 CSS、代码、新组件或自由布局。

## 已确认的使用流程

1. 打开工作室，默认以当前主题为基础；用户也可选择重新设计。
2. 输入多句要求，可附参考图或实际壁纸。两类图片在界面上明确区分。
3. 默认沿用 DSH 当前模型；有参考图时检查图片输入能力，不支持则保留输入并提示选择支持看图的模型。
4. 用户能看到本轮发送给模型的图片；提交后允许取消。
5. AI 提出主题修改，解释本轮改动和无法满足的要求。
6. 对输出执行结构、字段范围、资源引用和可读性校验，通过后更新预览并建立新版本。
7. 校验失败自动修复一次；仍失败则解释原因，保留上一版有效草稿。网络错误等失败也保留草稿。
8. 用户继续反馈。默认只改本轮涉及的字段；明确要求整体重做时才重新设计。
9. 可回到任意历史版本继续修改。关闭工作室后，本地保留未完成会话，并提供删除入口。
10. 满意后点击保存并应用，复用现有保存规则与正式配置持久化能力。

参考图用于理解视觉风格；截图不会自动成为壁纸。用户另传的干净壁纸可供使用。首版不包含截图去除窗口、图标或 AI 生成新壁纸的能力。

## 内部接口与数据流（实施建议）

工作室对话界面 → 插件宿主调用通道 → DSH 模型服务 → 结构化修改结果 → 校验与草稿合并 → 预览。

建议定义独立的主题设计请求与结果，不允许模型返回整份宿主配置：

- 请求：会话标识、请求标识、基准版本、用户要求、必要的消息历史、当前外观草稿、明确选择的图片附件引用、模型选择、局部修改或重新设计模式。
- 结果：基准版本、受支持字段的修改集合、改动说明、无法满足的要求。
- 控制：取消请求；能力或服务不可用时返回可理解的错误。

由程序维护主题标识、历史版本和壁纸资源映射。模型只能修改允许的外观字段，不能修改凭据、性能设置、其他主题或会话存储。图片中的文字按参考内容处理，不作为操作指令。

先校验原始输出，再执行规范化与合并，避免自动纠正配置的逻辑掩盖模型输出错误。局部修改中未出现的字段保持原值；重新设计也必须通过同一套校验。

每次请求绑定基准版本。取消、回退或切换会话后，旧请求的迟到结果不能覆盖当前草稿。未完成或未通过校验的流式输出不进入有效版本。

## 会话与版本（实施建议）

本地保存消息、参考图引用、壁纸引用和有效草稿版本。回退后继续修改形成新的版本关系，保留此前有效版本。删除会话时清理仅由该会话持有的图片，不删除正式主题仍在使用的壁纸。

模型凭据交由宿主管理，不进入会话或风格包。保存主题与保存设计会话是两件事：导出的主题风格包继续使用现有格式，不附带设计对话或参考图。

## 可复用的项目能力

- `src/studio/Studio.tsx`：草稿编辑、预览与保存入口。
- `src/studio/model.ts`：主题草稿及可读性检查。
- `src/config/types.ts`、`src/config/validation.ts`：配置类型与规范化。
- `src/workspace/sharing.ts`：`dsh-style-pack` v1 风格包导入、合并与导出。
- `src/workspace/wallpaper-colors.ts`：本地图片取色，可辅助设计，但不能代替模型理解参考图。
- `src/client/index.tsx`：真实宿主临时预览路径。

本地依赖提供 `ctx.llm.stream()`、图片消息和附件服务，以及默认模型选择接口。接口存在不等于实际运行宿主已加载相关服务，也不证明所选模型具有图片理解能力，开发时需验证。

## 验收标准

- 多句文字需求能产生合法主题草稿，并说明修改内容。
- 支持图片的模型能利用参考图生成现有字段可表达的主题；图片不会误设为壁纸。
- 输入“只把文字调亮”时，其余主题字段保持不变。
- 连续多轮修改后可以回退，并从旧版继续设计。
- 关闭重开后可以继续未完成会话，且支持删除。
- 不支持图片、服务不可用、生成失败、校验失败和取消均不会覆盖有效草稿。
- 自动修复最多一次；迟到结果不能覆盖用户已切换的版本。
- 生成和工作室预览不持久化正式主题；只有用户明确保存应用才更新正式配置。真实宿主试用沿用可恢复的临时预览机制。
- 保存后的主题能通过现有风格包导出、导入链路复用，不携带对话、参考图或凭据。
- 在真实 Electron 宿主验证配色、字体、壁纸和支持的材质效果；工作室代表性预览不视为所有宿主页面的完全还原。

## 开发顺序（实施建议）

1. 验证宿主模型、图片与调用通道，完成文字要求到合法草稿的最小闭环。
2. 增加工作室对话、图片选择、修改说明及取消和错误处理。
3. 增加多轮历史、本地恢复、删除及回退后的请求隔离。
4. 连接真实宿主试用和保存应用，按上述标准完成验证。

# 执行与交付门禁

## 状态与修正预算

正常流程：`brief → needs-input? → planned → staged → rendered → checked → preview-ready → user-approved → applied`。

任何工作阶段都可以进入 `cancelled` 或 `blocked`；保留最后有效草稿。预览中的用户反馈形成新设计请求，继承此前决定。部分尺寸或阶段可以实时展示，但标明“处理中/待验收”，不能提前显示最终通过。

首次生成不算修正。收到技术或视觉问题后重新修改并检查，算一轮修正；相互独立的问题可以合并。一个用户请求最多三轮自动修正；工具协议重试计入独立的调用预算，不能无限重试或重置设计轮数。

## 验收矩阵

| 检查项 | 证据与合格标准 | 失败处理 |
|---|---|---|
| 意向覆盖 | 每条明确要求映射到决定、图层/参数或已说明的阻碍；禁止项没有被采用 | 补设计或追问关键冲突 |
| 设计完整度 | 七项职责全部有决定、实现引用与验证方法；局部修改正确继承旧版本 | 缺项不标记完整作品 |
| 素材 | 实际资源可读取、哈希一致、用途与使用依据已核验、无未授权的参考图转换 | 阻止纳入作品；换素材/生成/询问 |
| 程序 | 后端/语言可用；隔离、编译、复杂度、引用和执行预算均通过 | 阻止执行，返回具体位置与预算信息 |
| 构图 | 主要视口、内容/输入/菜单及滚动状态下主体与操作完整，装饰遵守保护区 | 修正位置、裁切、遮罩或密度 |
| 可读性 | 根据实际合成背景与派生前景检查所有规定的文字/状态配对，达到运行时硬阈值 | 优先修正阅读面、文字和功能强调，不降低阈值 |
| 连续动态 | 记录周期/时间范围、种子、关键与极值相位；保护区及合成范围可约束 | 无法证明持续可读时采用稳定阅读面或静态回退 |
| 性能与生命周期 | 在规定设备档位、尺寸和 DPR 下测量帧耗时、内存/资源；隐藏暂停，切换/取消/销毁不残留 | 在预算内简化；记录并复测静态降级 |
| 静态与无障碍模式 | 减少动态/透明时仍有完整且清楚的设计，焦点/选中/错误可辨认 | 生成对应版本后重检 |
| 恢复与迁移 | 重开、回退、离线恢复、导出后独立导入，图层/程序/素材关系一致 | 阻止正式交付；明确缺失内容 |
| 视觉意向 | 视觉模型对真实画面逐项指出可见依据与问题；未知项保留未知 | 调整设计；无视觉模型转人工审阅 |
| 用户审美 | 用户针对具体版本确认满意或提出反馈 | 继续对话，不用检查结果否定用户感受 |

## 硬检查、视觉检查与用户确认

结构、素材、程序权限/预算、保护区、阅读门槛、性能和迁移属于程序硬检查。模型判断不能覆盖硬失败。

视觉一致性、意向表达和整体细节由视觉评估辅助判断，保留具体截图依据。模型没有看到实际画面时，该项为未知。单次检查和几个动画截图只证明采样结果；持续可读性需要保护策略或可验证的变化范围。

缺少视觉模型可以交付明确标注的人工审阅预览；用户对该版本的确认可以完成审美审阅，但不能绕过硬失败。保存应用始终需要用户确认具体版本。

视觉模型认为“不够像”或“不够协调”时，先说明具体问题并允许用户判断。用户明确表示已经审阅并接受当前视觉结果，可由运行时签发 `reviewMode: manual` 的确认回执，保留模型意见并完成审美验收；模型不能代替用户签发该回执。此人工确认仍不能绕过技术硬失败。

## 证据有效性

工具回执必须由运行时登记，绑定当前设计摘要、基准版本和能力版本。视口、状态、种子、相位与测量方法必须能复现。修改设计后重新获取相关证据；只有运行时能判断未受影响的证据是否可复用。

当前检查批次由运行时指定，并参与回执绑定。门禁读取该批次全部报告，包括模型未引用的失败报告。只有运行时启动并完成的新检查批次可以取代旧批次；历史失败仍保留以便追溯，但不永久阻塞经过完整重检的设计。

报告区分 `pass`、`fail`、`unknown`、`not-applicable`。最后一项必须由规则允许并给出理由，例如无程序资源时无需程序执行检查；不能以“模型认为不需要”跳过阅读或实际渲染检查。

## 对用户的交付内容

提供实际预览、简短设计命题、主要决定与变化、素材用途及来源、自动修正/降级、未满足项和验收状态。保留可编辑设计文档、图层、程序、资源及静态回退。工程字段和冗长报告保留在诊断中，不要求用户填写这些字段。

## 可观测效果与真实宿主回归

图层名称和文字说明不是效果证据。核对最终合成中的实际可见影响，区分静态、整体位移、控制点/尺度形变、旋转与明暗变化；它们不互相替代，也不单独证明某种自然意向已经实现。低密度与慢速不能成为近乎不可见的理由。

检查背景与文字的真实前后层级。不得把画布覆盖整个界面后逐字挖洞当成阅读保护；不得用独立画布通过代替滚动场景验收。持续滚动不能出现随文字移动的缺口、色块、高亮或全屏闪动。输入、菜单与浮层应使用稳定表面。

无视觉模型时，可依据实际程序与浏览器量化报告审查结构/意向一致性，但必须标注未看图，不能由此宣称审美或视觉意向已验收。

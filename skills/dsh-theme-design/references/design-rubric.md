# 设计职责与判定标准

完整创作的每一项职责均须有决定、实现引用和检查方法。局部修改只修改相关部分，同时复查受影响的职责；继承的决定必须引用基准版本，不能把“未修改”算成漏设计。

## 1. 意向与视觉语言 `intent`

- 输入：用户原话、素材、会话决定和保留项。
- 判定：区分主体意向、情绪、视觉关系和功能用途。例如“轻盈”可能体现为留白、疏密、细线或缓慢运动，依据当前语境选择；同一个词不绑定某套预设。
- 处理：用简短设计命题连接意向与视觉结果，记录推断。明确关键参考中采纳的是构图、形态、色彩、质感还是节奏。
- 验证：每条明确要求都有对应设计决定、实现引用或已说明的阻碍；视觉模型的判断引用实际画面。缺少决定性信息按需追问。

## 2. 构图与层次 `composition`

- 输入：视口、宿主可作用区域、阅读/输入区、素材角色与意向。
- 判定：明确视觉重心、层级、留白、比例、前后景、疏密和视线路径。主体素材应有显式焦点；重复图案需决定尺度、间隔与重复关系。
- 处理：把背景、图案、材质、主体、光影、局部装饰分别映射到有顺序的图层；用逻辑区域与相对坐标适配，不依赖偶然的 DOM 类名。
- 验证：在最窄与最宽支持视口检查主体裁切和层级；检查长文、会话、输入、菜单与滚动状态。装饰不遮挡操作，不捕获点击，不改变宿主功能布局。
- 失败：先调整裁切、缩放、位置、疏密或遮罩；仍不能满足主体完整性时询问用户在完整显示与铺满之间的取舍。

## 3. 色彩、排版与阅读 `colorAndReading`

- 输入：视觉语言、现有字体、主体色、阅读时长及内容区域。
- 判定：区分大面积表面色、阅读色、功能强调色与装饰色。淡雅可以由背景、材质和低密度装饰体现，功能文字仍需满足对比度。状态含义同时使用标记或图形，不依赖颜色单独表达。
- 处理：定义主辅色比例、明暗层次、字体层级、行高和信息密度。保留用户指定字体；字体未安装时使用可用回退并报告，不能假装已安装。
- 验证：按运行时公布的配对阈值检查实际合成后的文字、按钮、选中、焦点和状态。对动态背景采用可证明的颜色范围约束或稳定阅读表面；几张截图不能证明所有动画时刻均合格。
- 失败：优先修改文字、强调色或阅读面保护，保留图案主体与装饰意向。复查派生文字与按钮前景，不降低硬阈值。

## 4. 图案、纹理与素材 `patternsAndAssets`

- 输入：用户素材、检索结果、原生绘制能力及图案意向。
- 判定：选择几何/路径绘制、程序纹理、粒子、素材合成或图像生成等合适方法；依据视觉特征选择，不把“听不懂的意向”自动改成纯色。
- 处理：明确形状、轮廓、重复关系、方向、尺度、纹理频率、密度、遮罩、混合与素材用途。可组合多种方法，但每层应有可说明的作用。
- 验证：与参考的采纳维度核对，检查拉伸、接缝、过密、摩尔纹、素材残留文字和跨尺寸变化。执行素材规则的全部前提。
- 失败：修改表达方法或选择替代素材；工具不足时指出具体缺失能力与仍可实现的方向。

## 5. 材质、光影与空间 `materialsAndLighting`

- 输入：表面角色、空间关系、素材与可用材质能力。
- 判定：决定粗糙/光滑、通透/实心、软/硬等视觉关系，以及光源方向、阴影、高光和深度依据。不要求每套主题都叠加全部材质效果。
- 处理：为不同区域定义材质参数与层级；真实采样、折射、位移只能在对应工具可用时声称实现。模糊、透明和描边按各自的实际行为命名。
- 验证：检查材质与主体一致性、边缘细节、光照方向、文字清晰度和透明叠加；低性能或减少透明模式要有对应版本。
- 失败：简化材质或使用静态表达，说明失去的视觉特征。

## 6. 动态与交互状态 `motionAndStates`

- 输入：用户动态偏好、意向节奏、注意力区域、性能能力。
- 判定：决定哪些关系随时间变化、速度和幅度、周期/非周期、空间范围、输入时行为。安静或静态需求优先解释为相应节奏，不强加持续动画。
- 处理：动画使用可取消、受预算限制的程序和可复现时钟；区域、遮罩、内容避让与静态回退是设计的一部分。焦点、选中、悬停和错误状态保持可辨认。
- 验证：在多个动画相位、交互和滚动状态检查闪烁、干扰、性能与越界。隐藏时暂停，减少动态时保留有意义的静态构图，销毁后释放资源。
- 失败：依次降低实例数、采样/着色复杂度、分辨率或更新频率，必要时采用静态版本；记录降级结果。

## 7. 适配、资源与交付 `adaptationAndDelivery`

- 输入：设备与视口能力、静态/动态方案、主题库和资源清单。
- 判定：区分随视口缩放的内容、固定视觉密度的内容，以及需要重排或重新裁切的内容。每项外部资源有稳定引用和来源。
- 处理：将可编辑的设计文档、程序、素材、静态回退和依赖版本一起打包。保留用户反馈、设计版本和引用关系；按能力提供重开、回退、删除与导入导出。
- 验证：重开与离线恢复、跨视口、资源缺失、导出后重新导入都需检查；分享包排除对话、凭据和仅作参考的图片。
- 失败：未完成迁移或缺少资源时保留草稿，返回明确错误，不能静默丢掉图层后宣称完整安装成功。

## 完整度与审美

七项职责要求完整的决定，不要求相同的画面，也不要求同样数量的图层。用结果证明意向：主体关系、构图、材质与节奏能否共同表达目标，是否出现与用户禁止项冲突的元素。用户认为“不像”“太满”“太冷”等属于设计反馈，应回到对应决定和实现修改，不能用程序检查通过反驳审美反馈。
